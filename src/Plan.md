# Трекер обработки фотозаказов — схема проекта

Состояние на 10.11.2026 (добавлена цена заказа). Версия 1: консольное приложение, данные в памяти.

## Зачем

Ответы на три вопроса:

| Вопрос | Метод `Tracker` |
|---|---|
| Что горит сегодня (этапы со сроком сегодня и просроченные) | `stagesDueToday(LocalDate today)` |
| Сколько проектов в работе | `ordersInProgress()` |
| Ближайший срок сдачи | `nearestDeadline()` |

## Перечисления

### `ShootType` — тип съёмки

| Константа | Название | Срок сдачи, дней | Ретушь, мин/кадр | Цвет, мин/100 кадров |
|---|---|---|---|---|
| `WEDDING` | Свадьба | 14 | 1.0 | 10.0 |
| `REPORTAGE` | Репортаж | 7 | 1.0 | 5.0 |
| `PORTRAIT` | Портрет | 5 | выбрать: 2.0 или 3.0 | 10.0 |

Справочно (для проверки расчётов в тестах, в enum не хранится — это данные конкретного заказа):

| Тип | Обычная длительность | Кадров в час | Остаётся после отбора |
|---|---|---|---|
| Свадьба | ~8 ч | ~1000 | ~10% |
| Репортаж | 2–3 ч | ~2000 | ~10% |
| Портрет | 1–2 ч | ~700 | ~15% |

Нормы — стартовые. Уточняются по фактическому времени этапов (с первой съёмки 14.11).

### `StageType` — этапы обработки (по порядку)

| № | Константа | Название | Норма времени |
|---|---|---|---|
| 1 | `CULLING` | Отбор | 3 мин на 100 снятых кадров (общая для всех типов) |
| 2 | `COLOR` | Цветокоррекция | по типу съёмки, на 100 отобранных |
| 3 | `RETOUCH` | Ретушь | по типу съёмки, на отобранный кадр |
| 4 | `EXPORT` | Экспорт | не учитывается |
| 5 | `DELIVERY` | Отдача (загрузка в облако) | не учитывается |
| 6 | `REVISIONS` | Правки клиента | 1 день |

### `StageStatus` — состояние этапа

| Константа | Смысл |
|---|---|
| `NOT_STARTED` | не начат |
| `IN_PROGRESS` | в работе |
| `DONE` | завершён |

## Константы

| Имя | Значение | Где |
|---|---|---|
| `CULLING_MINUTES_PER_100` | 3 | общая норма отбора |
| `PROCESSING_HOURS_PER_DAY` | 3 | по нижней границе 3–5 ч, с запасом |
| `REVISION_DAYS` | 1 | день на правки перед сдачей |

## Классы

### `Stage` — этап конкретного заказа

| Поле | Тип | Когда известно |
|---|---|---|
| тип этапа | `StageType` | сразу |
| статус | `StageStatus` | меняется |
| плановое время | минуты (`double`) | после того, как известны кадры |
| фактическое время | минуты (`double`) | после завершения — для статистики |
| срок | `LocalDate` | вычисляется от срока сдачи |

| Метод | Что делает |
|---|---|
| `start()` | статус → `IN_PROGRESS` |
| `finish(actualMinutes)` | статус → `DONE`, сохраняет факт |
| `isDueToday(LocalDate today)` | срок сегодня и этап не завершён |
| `isOverdue(LocalDate today)` | срок прошёл и этап не завершён |

### `Order` — заказ

| Поле | Тип | Когда известно |
|---|---|---|
| клиент | `String` | сразу |
| тип съёмки | `ShootType` | сразу |
| дата и время съёмки | `LocalDateTime` | сразу |
| часы съёмки | `double` | сразу |
| цена | `int`, целые рубли | сразу (вводится вручную, своя для каждой съёмки) |
| снято кадров | `int` | после съёмки |
| отобрано кадров | `int` | после отбора |
| этапы | `List<Stage>` | создаются вместе с заказом |

| Метод | Что делает |
|---|---|
| `getPrice()` | цена заказа в рублях |
| `deadline()` | дата съёмки + `shootType.getDeadlineDays()` (вычисляется, не хранится) |
| `cullingMinutes()` | снято кадров × `CULLING_MINUTES_PER_100` / 100 |
| `colorMinutes()` | отобрано × `shootType.getColorMinutesPer100()` / 100 |
| `retouchMinutes()` | отобрано × `shootType.getRetouchMinutesPerFrame()` |
| сроки этапов | назад от `deadline()`: минус `REVISION_DAYS`, затем ретушь, цвет, отбор; минуты → дни через `PROCESSING_HOURS_PER_DAY`, округление вверх (`Math.ceil`) |

Принцип: заказ знает свои кадры и спрашивает нормы у своего типа.

### `Tracker` — список заказов (логика, без `Scanner`)

| Метод | Что возвращает |
|---|---|
| `addOrder(Order)` | — |
| `stagesDueToday(LocalDate today)` | этапы со сроком сегодня + просроченные |
| `ordersInProgress()` | число заказов, где не все этапы `DONE` |
| `nearestDeadline()` | ближайший срок сдачи среди незавершённых заказов |
| `earningsForMonth(int year, int month)` | сумма цен заказов со съёмкой в этом месяце |
| `totalEarnings()` | сумма цен всех заказов за всё время |

## Открытые вопросы

| Вопрос | Решение |
|---|---|
| Кадры ещё не сняты — чему равны плановые минуты и сроки этапов? | решить при реализации |
| Норма ретуши портрета: 2 или 3 мин? | выбрать при создании enum |
| «Сегодня» в методах | только параметром `LocalDate today`, не `LocalDate.now()` внутри — для тестов |
| Цена 0 (бартер, подарок) — допустима? | по умолчанию `>= 0`; изменить, если не нужно |
| Заработок в час | позже: цена / (часы съёмки + фактические часы обработки), когда этапы начнут хранить факт |
| Деление в расчётах | только дробное (`/ 60.0`, `double`) |

## Пример для тестов (свадьба)

| Величина | Расчёт | Значение |
|---|---|---|
| Снято кадров | 8 ч × 1000 | 8000 |
| Отобрано | 10% | 800 |
| Отбор | 8000 × 3 / 100 | 240 мин |
| Цвет | 800 × 10 / 100 | 80 мин |
| Ретушь | 800 × 1.0 | 800 мин |
| Срок сдачи | 14.11 + 14 дней | 28.11 |
| Правки | 28.11 − 1 день | с 27.11 |
| Ретушь, дней | ceil(800 / 60.0 / 3) | 5 |
